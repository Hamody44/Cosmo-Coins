# البوت الثاني: `$say` و`$ping` و`$numbers`

هذا بوت Discord مستقل بلغة Python باستخدام `discord.py-self`، ولا يمرر إعداد `Intents`. يوجد بالكامل داخل `second_bot/` ويعمل بتوكن حساب المستخدم. يستخدم وضع account-client الذي يسمح له بمعالجة أوامر يرسلها حساب آخر؛ أما `self_bot=True` في المكتبة فيعني تجاهل رسائل الحسابات الأخرى، لذلك لا يُستخدم هنا. عند كتابة `$say hi` ينتظر ثانية واحدة، ثم يحذف رسالة الأمر ويرسل `hi`. يسمح باستخدامه لمالك الحساب أو لأي عضو يحمل الرتبة المحددة في `SAY_ALLOWED_ROLE_ID`. يعرض الأمر `$ping` حالة الاتصال وزمن استجابة Discord بالميلي ثانية بعد تأخير ثانية واحدة. يتيح `$numbers` أو `$استخراج_الأرقام` إرفاق صورة لاستخراج الأرقام الظاهرة فيها عبر Gemini Vision، مع حد 8 ميغابايت. لا يستخدم هذا البوت أوامر السلاش؛ فهو يعالج أوامر البادئة فقط. يقبل البوت الأوامر فقط في السيرفرات التي يوجد فيها بوت Cosmo-Coins الأساسي أيضًا؛ ينشر البوت الأساسي قائمة سيرفراته محليًا كل 30 ثانية، ويتجاهل البوت الثاني الأوامر إذا غابت القائمة أو تجاوز عمرها 90 ثانية.

## الإعداد

1. جهّز الحساب الذي سيعمل به self-bot وفق إعداداتك، ثم استخدم توكن الحساب المخصص له.
2. انسخ `second_bot/.env.example` إلى `second_bot/.env`، ثم أدخل `SECOND_BOT_TOKEN` و`SAY_ALLOWED_ROLE_ID`. أضف `GEMINI_API_KEY` لتفعيل `$numbers`، ويمكنك تغيير `GEMINI_VISION_MODEL` اختياريًا. لا يقبل البوت الثاني `DISCORD_BOT_TOKEN` كبديل، لتفادي استعمال توكن البوت الأساسي عند غياب إعداد توكن منفصل. قيمة الرتبة هي **Role ID** من السيرفر، وليست اسمها. فعّل Developer Mode في Discord ثم اختر Copy ID. لا تشارك التوكن أو مفتاح Gemini ولا تضعهما في Git.
3. لا يحتاج البوت الثاني إلى إعداد `Gateway Intents` في هذا الوضع. يظل البوت الأساسي منفصلًا ويستخدم `Intents` الخاصة به.
4. جهّز وصول البوت الثاني إلى السيرفرات المطلوبة وفق إعدادات Discord الحالية، مع الصلاحيات المذكورة أدناه.

## الصلاحيات المطلوبة

- **View Channels** و**Send Messages** في القنوات التي سيعمل فيها.
- **Manage Messages** حتى يتمكن من حذف رسالة الأمر التي كتبها المستخدم.
- في سلاسل النقاش (Threads)، امنحه أيضًا **Send Messages in Threads**.
- لا يحتاج البوت إلى صلاحية `Administrator`. إذا لم تتوفر صلاحية الإرسال، فسيسجّل ذلك في الطرفية لأن Discord لن يسمح له بإرسال رسالة خطأ داخل القناة.
- يقبل `SECOND_BOT_TOKEN` توكن الحساب الذي سيعمل به self-bot، ويمكن إدخاله خامًا أو مع بادئة `Bot ` اختيارية عند استخدام توكن بوت متوافق.

يستخدم البوت `discord.AllowedMentions.none()` لكل ما يرسله، لذلك لا يؤدي النص إلى تنبيه أشخاص أو أدوار أو `@everyone`.

## تثبيت التبعيات

تُثبّت كل مجموعة متطلبات في بيئة افتراضية مستقلة لتجنب تعارض تبعيات البوتين. سكربت `run_bots.sh` ينشئ البيئات الافتراضية ويثبت أو يحدّث المكتبات تلقائيًا عندما يتغير ملف `requirements.txt`، لذلك لا تحتاج إلى تعديل السكربت عند إضافة مكتبة جديدة. للتثبيت اليدوي من جذر المستودع:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt

python3 -m venv second_bot/.venv
second_bot/.venv/bin/python -m pip install --upgrade pip
second_bot/.venv/bin/python -m pip install -r second_bot/requirements.txt
```

قبل التشغيل، أنشئ أيضًا ملف `.env` الخاص ببوت Cosmo-Coins في جذر المستودع وفق إعداداته الحالية، إن لم يكن موجودًا بالفعل. لا تستبدل ملف `.env` قائمًا.

## تشغيل البوتين معًا

من جذر المستودع:

```bash
chmod +x run_bots.sh
./run_bots.sh
```

يشغّل السكربت `main.py` الخاص بـ Cosmo-Coins من جذر المستودع، ثم يشغّل `second_bot/main.py` من مجلد `second_bot/`؛ وبذلك يقرأ كل بوت ملف `.env` الخاص بمجلده وبيئته الافتراضية. إذا لم توجد بيئة افتراضية لأحدهما، يستخدم السكربت `python3` المتاح. أوقف البوتين معًا باستخدام `Ctrl+C`.

يمكن تشغيل البوت الثاني وحده للاختبار:

```bash
cd second_bot
.venv/bin/python main.py
```

إذا كانت الاستضافة تسمح بتشغيل ملفات Python فقط، اجعل ملف التشغيل هو `run_bots.py` الموجود في جذر المستودع. هذا الملف يشغّل `run_bots.sh` تلقائيًا من المسار الصحيح، مع إبقاء بيئة كل بوت منفصلة:

```bash
python3 run_bots.py
```

## سلوك الأمر والأخطاء

- `$say hi` ينتظر ثانية واحدة، ثم يحذف رسالة الأمر ويرسل `hi` دون تفعيل المنشنات.
- `$ping` ينتظر ثانية واحدة ثم يعرض أن البوت متصل وزمن استجابة Gateway الحالي بالميلي ثانية.
- `$numbers` يحتاج إلى صورة مرفقة مع الرسالة، ثم يعرض الأرقام بترتيب ظهورها باستخدام Gemini. الصور المدعومة هي JPEG وPNG وWebP وGIF، والحد الأقصى 8 ميغابايت. إذا لم يكن `GEMINI_API_KEY` مضبوطًا، تظهر رسالة إعداد واضحة بدلًا من إيقاف البوت.
- يطبق هذا البوت الثاني cooldown شخصيًا مدته 30 ثانية لكل مستخدم وفي كل سيرفر. بوت Cosmo الأساسي لا يطبق cooldown.
- يستخدم `$numbers` افتراضيًا `gemini-3.8-flash`، ويمكن تغييره من خلال `GEMINI_VISION_MODEL`. يُرسل الطلب مباشرة إلى Gemini عبر HTTP، مع مهلة 20 ثانية للمحاولة. عند timeout أو أخطاء 503/429 يجرب مرة واحدة نموذج `gemini-2.5-flash-lite` كحل احتياطي، ثم يعرض رسالة واضحة بدل إظهار أن الصورة غير واضحة.
- يمكن تفعيل مزود مختلف كخطة احتياطية بعد فشل نماذج Gemini بإضافة `OPENROUTER_API_KEY` إلى `second_bot/.env`. يستخدم البوت `openrouter/free` افتراضيًا، وهو موجه مجاني يختار نموذجًا مجانيًا يدعم الصور تلقائيًا. توفر النماذج المجانية وسرعتها وحدودها قد تتغير، لذلك يظل Gemini هو الخيار الأول.
- تُقبل الأوامر فقط في السيرفرات المشتركة بين البوتين؛ تُرفض أوامر الرسائل الخاصة والسيرفرات غير المشتركة بصمت. عند تعذر قراءة حالة البوت الأساسي أو تقادمها، يتوقف تنفيذ الأوامر حتى تُستعاد الحالة الحديثة.
- يرفض النص الفارغ أو الذي يتجاوز 2000 حرف.
- تُرفض محاولة الاستخدام من شخص ليس مالك البوت ولا يحمل الرتبة المحددة.
- يتطلب حذف أمر العضو `Manage Messages`. عند نقصها تظهر رسالة واضحة ما دام للبوت إذن الإرسال.
- تُعالج أخطاء الأمر وDiscord وتسجّل في الطرفية بدل إيقاف البوت.

## اختبارات الوحدة

الاختبارات مكتوبة باستخدام `unittest` ولا تتصل بـDiscord ولا تحتاج رمز بوت حقيقي. بعد تثبيت متطلبات البوت الثاني، شغّلها من داخله:

```bash
cd second_bot
.venv/bin/python -m unittest discover -s tests -v
```

تغطي اختبارات الإعدادات، صلاحيات `!say`، حذف الرسالة، النص الفارغ وحد 2000 حرف، معالجة أخطاء الأمر، وتعطيل المنشنات ونتيجة `!ping`.

## تنظيف الملفات غير المستخدمة

لا يمكن تحديد أن ملف Python غير مستخدم بشكل موثوق من خلال الاسم فقط، خصوصًا لأن `cogs/` تُحمّل ديناميكيًا. لذلك يوجد `cleanup_unused_files.py` في جذر المشروع بوضع معاينة افتراضي، ولا يلمس قواعد البيانات أو ملفات `.env` أو `.runtime` أو النسخ الاحتياطية أو البيئات الافتراضية أو المكتبات المثبتة داخلها.

اعرض المخلفات القابلة للحذف والملفات المصدر التي تبدو غير مرتبطة دون حذف أي شيء:

```bash
python3 cleanup_unused_files.py --include-source
```

بعد مراجعة الناتج، احذف فقط المخلفات المولدة الواضحة مثل `__pycache__` وملفات `.pyc`:

```bash
python3 cleanup_unused_files.py --apply
```

الأداة ترفض حذف ملفات المصدر تلقائيًا؛ يجب مراجعة أي ملف مصدر يدويًا أولًا، لأن التحليل الساكن لا يستطيع اكتشاف كل الاستدعاءات الديناميكية أو الملفات المطلوبة من إعدادات الاستضافة.
